Engine fixes (src/):
- q/k normalization semantics (attn_qwen.c): the reference is rms_norm with
  eps on the MEAN (x/sqrt(mean(x^2)+1e-6) then inv_scale^2 / inv_scale for
  q/k); the engine used l2norm with eps on the SUM, which deviates for
  small-norm heads (433/2048 k elements off ~1%). Now exact: q/k match 0/2048.
- router input (main.c): the MoE router was fed the RAW post-attention state
  (rms 0.03 -> near-uniform softmax -> flat topk weights). The reference
  routes on post_attention_layernorm(state). Applied ffn_norm before the gate
  matvec. L0 router selection+weights now IDENTICAL to ref.
- shared expert silu (moe.c): chain was sigmoid(g)*up; reference is
  silu(g)*up = g*sigmoid(g)*up. L0 moe-acc 0.0122 -> 0.0131 (ref 0.0140).

  row-over-row input corruption once row r overwrote cur[0..511] while later
  rows still read cur. ux now tmp+M.

  worker threads raced on the flag -> mismatched expert data), --no-simd
